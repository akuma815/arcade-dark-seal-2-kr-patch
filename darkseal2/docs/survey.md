# Dark Seal 2 (Japan v2.1) — 초기 조사

작성 2026-10-04. 근거 이미지는 [evidence/](evidence/).

## 1. 하드웨어·ROM 적재 (FBNeo d_rohga.cpp WizdfireInit 로 확정)

| 항목 | 값 |
| --- | --- |
| CPU | 68000, 사운드 HuC6280. DECO 104 보호칩 |
| 프로그램 영역 0x000000~0x17ffff | `jb-01-3.3d`(상위)+`jb-00-3.3a`(하위) @0, `jb-03.5d`+`jb-02.5a` @0x40000, **부모 `mas13`(상위)+`mas12`(하위) @0x80000~0x17ffff (데이터 ROM)**. 스크램블 없음. `mas12/13` 은 앞·뒤 256KB 가 동일(미러) |
| 문자(8×8) ROM | `jb-04.10d`(짝수)+`jb-05.12d`(홀수) 인터리브 → **DECO 74 스크램블** → deco16 8×8 디코드. 부모 `je-04/05` 와 동일 내용 |
| 16×16 ROM | gfx1 = `mas00`+`mas01`(2MB, 레이어 0/1용), **gfx2 = `mas02`+`mas03`(1MB, 레이어 2/3용)** — 둘 다 DECO 74 스크램블 |
| 메모리 | pf_ram[0] 0x200000, [1] 0x202000, **[2] 0x208000**, [3] 0x20a000 (각 4KB=2048워드), 스프라이트 0x340000/0x360000, 팔레트 0x380000, RAM 0xfdc000~0xfe3fff·0xfe4800~0xffffff |
| 타일 뱅크 | `rohga_bank_callback`: 레이어 제어값으로 `((bank>>4)&3)<<12` 가 타일 인덱스에 더해짐. 프롤로그는 뱅크 0 으로 실측 |

복호 도구: `common/scripts/deco74.py` (테이블 `common/config/deco74_tables.json`). 복호본 `work/chars_decrypted.bin`, `work/gfx1_decrypted.bin`, `work/gfx2_decrypted.bin`.

## 2. 텍스트 레이어 (실측: Lua 덤프 frame 800/1000/1300)

- 프롤로그 표시 중 **0x208000 (pf_ram[2], 16×16 레이어)** 에만 타일 0xa04~0xaff 가 112셀. 8×8 레이어(0x200000/0x202000) 는 비어 있음.
- 즉 **2편의 일본어 본문은 폰트+스크립트가 아니라, 16×16 타일로 미리 렌더한 "그림 글자"** 다.

## 3. 글리프 타일 뱅크 (gfx2 = mas02/03, 8192타일 중)

| 타일 범위 | 내용 | 근거 |
| --- | --- | --- |
| **0x9c0~0xb3f (384타일)** | 프롤로그·게임 중 대사용 16×16 글자 (한자·가나·기호). 같은 글자는 같은 타일 재사용 | [evidence/gfx2_tiles_09c0_0cff.png](evidence/gfx2_tiles_09c0_0cff.png) |
| 0xdc2~0xe04 (67타일) | 스태프롤 문구("STAFF 原作·脚本…") 그림 글자 | [evidence/gfx2_tiles_0d80_0e1f.png](evidence/gfx2_tiles_0d80_0e1f.png) |
| 8×8 문자 ROM 0x20~0x7f | ASCII = 타일 인덱스 (0x60~ 소문자) ; 0xc0~0x13f 8×8 가타카나·히라가나, 0x200~ 히라가나 | [evidence/chars_0000_027f_x3.png](evidence/chars_0000_027f_x3.png) |
| gfx1(mas00/01) | 글자형 타일 없음(자동 판정) | — |

0x9c0~0xb3f 는 mas12/13 타일맵 블록들이 **384타일 전부** 참조한다 → 빈 슬롯 0. 한글 글리프는 기존 타일을 덮어쓰거나(글자 수요 ≤ 384 이면 가능) 다른 빈 타일 영역을 찾아야 한다.

## 4. 텍스트 데이터 (mas12/13 = 프로그램 영역 0x80000~)

- 메시지 화면 타일맵 블록 **0xa4950~0xa7f5a** (2,649셀, 고유 254타일, **20열 행 × 약 139행** — PoC-1 에서 RAM 열 = 블록 열로 실측; 행 0 = `0,0,ガ,リ,ア,…`): 프롤로그 4문단 + 게임 중 대사 상자(녹색 박스) 다수. 32열로 그린 참고 렌더: [evidence/prologue_block_0a4954.png](evidence/prologue_block_0a4954.png) (열 수가 달라 줄이 어긋나 보임).
- 그 밖에 0x9c0~0xb3f 를 참조하는 블록 99개(총 7,488셀) 탐지. 고유 타일이 1~3개뿐인 블록(0xa7f5c 이후, 타일 0xa88 반복)은 대사 상자 테두리/빈칸으로 추정. 0x8316e(262셀)·0x9d4e2(184셀, 셀=고유)·0xa371e·0xa39fe·0xb0fa8~0xb1490 은 미분류 — 렌더해 확인할 것.
- 그리기 경로: 0x11a7a 루틴이 `0x8fc14` 테이블(인덱스 RAM `0xfdc106`) → 청크 포인터 배열 → **20열×16행 청크(0x280바이트)** 를 스크롤값(`0xfdc146/0xfdc14a`) 기준으로 0x208000 에 복사(0x11b48). 메시지 블록이 청크 테이블 어디에 매여 있는지는 미확인.
- 프로그램 ROM 평문 ASCII: 0x2532 "SQUIRE LORD BARON COUNT DUKE KING" + 알파벳 표, 예외 메시지 등. HUD 는 8×8 ASCII 타일 사용 추정(미실측).

## 4b. 2026-10-04 추가 조사 — 폰트 공유 구조 (중요)

- 글리프 뱅크 실측: **0xa03~0xb4b (329타일)** 이 16×16 글자. 0x9c0~0xa02·0xb4c~0xb5f 는 그래픽(비글자). 전사표 329자 완료(`font/mapping/ds2_glyph_map.json`).
- 이 뱅크는 **여러 텍스트 화면이 공유**한다: (a) 메시지 블록 0xa4950(프롤로그 3 + 대사 상자 24, 27 레코드, `ds2_blocks.json`), (b) **하늘 배경 세로쓰기 스토리** 블록 0xa39fe(20열 타일맵에 세로 열로 배치, 「古老曰く…」 + 하단 상자 1줄), (c) NPC/상점 대사 0xab576·0xab5b4·0xabf78·0xac25c(일부 글자는 뱅크 밖 타일), (d) 엔딩 메시지 0xaead0~0xaee8e(파란 배경, 일부 뱅크 밖 타일), (e) 스태프롤 0xac738~ (STAFF 원작·각본…). 0x8316e·0x9d4e2·0xb125c·0x833a4 는 **타일 번호 순서대로 나열된 표**(글자 순서표 — 표시용 아님으로 추정, 소비자 미확인).
- 타일 스타일 2종: 프롤로그·하늘 스토리 = 배경 0(투명)·본체 7·외곽선 2 / 대사 상자·엔딩 = 배경 2(상자색)·본체 7. 같은 글자라도 두 문맥에 쓰이면 타일 2개 필요.
- **타일 예산 문제**: 메시지 27레코드 한글 초벌만으로 신규 타일 254(두 스타일) — 뱅크 329 중 메시지 사용분 265 안에서 겨우 수용. 하늘 스토리·NPC·엔딩·스태프롤까지 번역하면 단일 스타일로도 ~330 이상 → 초과. 어느 한 화면을 일본어로 남기면 그 화면의 타일을 보존해야 하므로 오히려 가용 타일이 준다(공유 폰트).
- kr #0 QA: 프롤로그·컷신 대사 OK, **하늘 스토리 화면 깨짐**(공유 타일 재배정 때문) — [evidence/kr_build0_attract_sheet.png](evidence/kr_build0_attract_sheet.png). → 사용자 결정(단일 스타일 + 하늘 스토리 검은 패널)으로 해소, [build.md](build.md).

## 4c. 하늘 스토리 장면의 스크롤 (디스어셈블로 확정, 2026-10-04)

- 어트랙트 스토리 루틴 0x1caa~0x1dfe. 초기화: 레이어 X 0xfdc16c=0x2c0·Y 0xfdc170=0x1f0, **텍스트 레이어 X 0xfdc17c=0x140(16.16 고정소수 long)·Y 0xfdc180=0x1fc**, 0xfdc184=0xa0. 페이드(0xfdc126 카운트다운) 뒤 루프 0x1d84: 매 프레임 `subi.l #$4000,$fdc17c`(−0.25px), `subi.l #$2000,$fdc184`, `addi.l #$4000,$fdc16c`; `andi.w #$3ff,$fdc16c` 가 0 이 되면(1280프레임) 종료 → `move.w #$80,d7; jsr $cc8`(d7 프레임 대기) → 페이드 아웃.
- 스크롤 레지스터 복사는 0x1020a~0x102b6: 0xfdc17c→0x310002, (0xfdc180+0xfdc134)→0x310004 등. 스테이지 카메라 0xfdc14a(속도 0xfdc196, 장면 표 0x44e8)와는 별개 경로 — 이 장면 동안 0xfdc14a=0.
- 화면 기하(캡처 실측): Y=0x1fc 에서 블록 행 r 의 셀 위 = 16r−20 → 원작 세로 텍스트가 쓰는 행 1~15 가 보이는 범위. 행 0 은 화면 밖.
- 패치 내용·근거는 [build.md](build.md) §3.

## 4d. 프로필 화면 (8×8 텍스트 경로, 2026-10-04)

- 2편의 유일한 **8×8 폰트 텍스트 화면**. 어트랙트 1주기 = 블록 4~8(카를·프레이아·호크·제이드·에미나, 초상+스탯), 2주기 = 블록 9~11(다크 나이트·제논·4마술사, 본문만). 블록 = 40×32 워드 타일맵(포인터 배열 0xb5288 = *(0x9c27c+0xc)), 로더 0x1045a 가 pf0 0x200000 에 행 간격 128B 로 복사. 호출부 0x3c7a/0x3dc4.
- 문자 ROM(jb-04/05, 4096타일): 0xeb8~0xf79 가 프로필 폰트(라벨 영문, 가타카나·히라가나·한자 소수, 숫자), **0x928~0xbff 는 공백 타일 728개**(한글 수용). 0xc00 = 상자 채움(공백, pal 5).
- 원본 ROM 에 영문판 프로필 스크립트(ASCII, 0x6a12 "The Knight. Hero of thousand battles." 등)가 남아 있으나 일본판은 쓰지 않는다. 예외: ASCII 프린터 0x4c28(표 0x4c92: attr.w, dest.l, 바이트열, ff fe/ff ff)로 P4 에 "Morning Star"(인덱스 0x8c) 덧그림.
- HUD 숫자 프린터 0x2418(4비트 코드 → 표 0x4a54) 별도 — HUD 는 번역 대상 아님.

## 5. 패치 범위에 대한 함의

- 글리프(gfx2 `mas02/03`)·타일맵(`mas12/13`) 모두 **부모 `wizdfire.zip`** 에 있다. 클론 고유 ROM(`jb-00/01/06`)에는 일본어 본문이 없다. → 2편 한글 패치 = 부모 ROM 4개 수정. FBNeo IPS 는 세트별로 적용되므로 darkseal2 실행 시에만 적용 가능.
- 한글 삽입 = (1) 한글 문장을 16×16 셀 그림으로 렌더 → 고유 글자 타일 생성, (2) 0x9c0~0xb3f(및 필요 시 추가 영역) 타일 교체, (3) 타일맵 블록의 셀을 새 타일 번호로 재작성. 코드 훅 불필요(그래픽 텍스트 경로). 글자 수요가 384 를 넘으면 빈 타일 영역 확보 필요.
- `mas12/13` 미러 2벌 모두 갱신한다(어느 쪽을 읽는지 미확인).

